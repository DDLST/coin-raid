# Разбор исходного проекта и результат правок

Проверен код ветки `main` на коммите `3186059b6c07881b5bbe3b2f6017dd327aea5bcf`. Исходные `npm ci` и `npm run build` прошли. До переработки игра уже собиралась: основной задачей было сделать её устройство понятным и обеспечить проверяемый перенос логики.

## Что мешало поддержке

В `GameScene.ts` одновременно находились ресурсы героя, поведение противников, все варианты атак, деревни, задания, интерфейс, сохранения и сюжет. Файл занимал 1466 физических строк, но многие строки содержали целые функции. После обычного форматирования тот же код занимал около восьми тысяч строк. Поэтому число строк исходного файла скрывало фактический объём.

Большинство вспомогательных модулей лежало в одной папке `src/game`. Названия `events`, `art`, `world`, `progression` требовали сначала открывать файл, чтобы отличить данные, правила, графику и выполнение действий. Поиск `hp` приводил одновременно к здоровью героя, врагов, полосам интерфейса и схеме сохранения.

В Git хранились 96 файлов `:Zone.Identifier`. Это служебные метки загрузки Windows; игра на них не ссылалась. Готовые сборки также находились в репозитории, но их назначение отличается: `docs/` используется для сайта, `PLAY.html` + `play/` — для автономного запуска. Удаление обеих папок под видом мусора лишило бы проект подготовленных вариантов распространения.

До правок в `package.json` были команды проверки типов и сборки. Отдельного набора регрессионных тестов и workflow проверки pull request в репозитории не было. При большом переносе методов одна успешная компиляция не проверяет, например, получение награды два раза или восстановление старого сохранения.

## Что изменено

Из сцены вынесены 160 методов в 18 систем. Созданы пять именованных групп состояния: герой, мир, путешествие, интерфейс и графика. Контроллеры получают типизированную ссылку на сцену; обращения между системами видны в коде. Порядок обновления остался в `GameScene.update()`.

Формулы и численные параметры отделены от создания объектов. `CombatRules.ts` содержит правила HP, выносливости и атак. `EnemyConfig.ts` содержит базовое здоровье и вычисление характеристик противников. Отдельные контроллеры обрабатывают бой, мир, магазины и сохранения. Источники музыки и иллюстраций сохранены вместе с авторством и лицензиями.

Все исходные TypeScript-файлы, стили, HTML и скрипты сборки отформатированы. В TypeScript включены дополнительные проверки неиспользуемых локальных объявлений и параметров. Добавлены единый форматировщик, тесты правил и браузерных сценариев, а также workflow `Check game` для push и pull request.

Карта `guide/index.html` содержит поиск, пятнадцать входов через игровые механики, описание файлов, список объявлений и просмотр кода с номерами строк. Она работает без сервера и включает текст текущих исходников. `SOURCE_INDEX.md` даёт ссылки на символы в GitHub. Команда `npm run docs:map` обновляет оба представления после правок.

Формат сохранения и его ключ не менялись. Для проверки получены две фикстуры из исходной игры: ручное сохранение v10 и характеристики всех 96 сочетаний типа врага с биомом. Новые тесты сравнивают параметры с этим исходным результатом, без повторного написания формул в тесте.

Браузерный набор создаёт контролируемые игровые ситуации. Для проверки обоих состояний каждого босса он ускоренно вызывает действия и проверяет созданные опасные зоны. Это проверка логики и связей после переноса; полное восьмибиомное прохождение обычным игроком по времени не выполнялось. Другие браузеры, субъективное удобство управления и баланс сложности отдельно не оценивались.

## Что остаётся учитывать

Связи систем не устранены полностью. Бой сообщает о попадании заданиям, смерть запускает переход мира, покупка меняет профиль и внешний вид, загрузка восстанавливает несколько систем. Эти связи обозначены явно через контекст сцены. При дальнейшем росте можно постепенно вводить более узкие интерфейсы, когда появятся конкретные потребители; сейчас отдельная инфраструктура событий для каждого поля усложнила бы чтение.

`TextureFactory.ts` остаётся большим, поскольку содержит код рисования и нарезки разных атласов. `ActorRenderer.ts` объединяет согласованную отрисовку персонажей, оружия и эффектов. `src/style.css` сохраняет порядок CSS-правил и переопределений предыдущих версий. Их дальнейшее дробление требует самостоятельной задачи с визуальным сравнением; текущая переработка не меняет каскад стилей и рисунки.

Сборщик предупреждает о размере общего JavaScript-пакета: в него входит Phaser и код игры. Само разделение TypeScript по папкам не уменьшает автоматически размер загрузки и не доказывает прирост FPS. Рефакторинг не заявляет таких улучшений. Музыка и атласы в сборке сайта остаются отдельными ресурсами, а автономный вариант сохраняет локальные части ресурсов.

Некоторые подписи карточек содержат численные значения прямо в тексте. При смене баланса следует согласовать формулы и описания, особенно цену усилений, лечение и фазы приёмов. Практические точки изменения перечислены в [PROJECT_MAP.md](PROJECT_MAP.md).
