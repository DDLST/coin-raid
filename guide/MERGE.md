# Загрузка архива в GitHub

Архив содержит полный проект версии 10.2.0, готовый сайт `docs/`, автономную игру `PLAY.html` с папкой `play/` и обновлённую карту кода `guide/index.html`. `.git` и `node_modules` в архив не входят.

## 1. Склонируй репозиторий

Открой PowerShell или терминал в папке, где хранишь проекты:

```sh
git clone https://github.com/DDLST/coin-raid.git coin-raid-updated
cd coin-raid-updated
```

Клонирование создаёт связь с GitHub и локальную историю в `.git`. Следующие команды выполняются внутри `coin-raid-updated`.

Архив подготовлен относительно коммита `7673a0b5975ff52c63072068e04ba4f08f49761a`. Проверить текущую вершину можно командой `git log -1 --oneline`. Если после него в репозитории появились собственные правки, сравни их перед заменой файлов.

## 2. Перенеси исправленные файлы

Распакуй ZIP **в отдельную папку**. Внутри будет папка `coin-raid` с `package.json`, `README.md`, `src` и остальным проектом.

В свежей клонированной копии замени папки `src`, `scripts`, `guide`, `docs` и `play` **целиком** соответствующими папками из архива. Сначала убери перечисленные старые папки из клона, затем скопируй новые. Простое объединение оставит удалённые и переименованные модули.

Затем скопируй корневые файлы из архива с заменой: `package.json`, `package-lock.json`, `index.html`, `PLAY.html`, README, CHANGELOG, LICENSE, сведения об ассетах, настройки TypeScript, Vite, Prettier и `.gitignore`. Включи показ скрытых файлов, если проводник скрывает настройки.

Удали старую папку `tests` и прежний файл `.github/workflows/check.yml`, если они остались: в публикуемой версии нет тестовых сценариев и их workflow.

Папку `.git` в клоне сохрани. Копировать нужно **содержимое** папки `coin-raid`, чтобы не получилось `coin-raid-updated/coin-raid/src`.

## 3. Проверь проект

Для готовой игры достаточно открыть `PLAY.html` двойным щелчком. Для полной проверки нужен Node.js 20.19 или новее:

```sh
npm ci
npm run verify
```

`verify` проверяет форматирование, типы, обе сборки и актуальность справочника. Если проверка завершилась ошибкой, разберись с ней до коммита.

Посмотри состав изменений:

```sh
git status --short
git diff --stat
```

Удаление прежних имён модулей и замена файлов готовой сборки ожидаемы. В изменениях не должно быть `node_modules`.

## 4. Создай коммит и отправь его

```sh
git add -A
git commit -m "refactor: clarify game architecture and configuration"
git push origin main
```

`git add -A` включает новые файлы, правки и удаления старых модулей. Обычный push сохраняет историю репозитория. Если Git запросит вход, пройди вход в свою учётную запись GitHub. Если push отклонён из-за новых удалённых коммитов, сначала получи и согласуй их; принудительная отправка для переноса архива не нужна.

После успешного push открой репозиторий на GitHub и проверь последний коммит. Если для GitHub Pages выбраны ветка `main` и папка `/docs`, сайт обновится из приложенной сборки после завершения публикации.

## Следующие изменения

```sh
npm run format
npm run docs:map
npm run verify
```

Сборочные каталоги `docs/` и `play/` обновляет `build:offline`, входящий в `verify`. Справочник обновляет `docs:map`. При изменении поведения добавляй запись в `CHANGELOG.md`.
